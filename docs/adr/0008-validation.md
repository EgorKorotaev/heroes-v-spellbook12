# ADR 0008 — Разделять доказательства и тестировать отдельные копии

Статус: принято. Дата: 2026-11-07.

## Уровни проверки

1. Исходные байты, SHA и преобразование геометрии: доказывают происхождение
   конкретного результата, не прохождение игры.
2. Unit-тесты без игры: формат, native-контракт, relocations, UV, skin bindings,
   швы новой бумаги и отказы builder.
3. Windows install round trip: владение файлами, проверка установки и rollback.
   Копии EXE используются как данные; игра не запускается.
4. Свежий игровой старт и кадры: запуск и видимая книга в конкретном процессе.
5. Наведение, перелистывание, действия и реальный каст: отдельные проверки.
6. Кампания, Save/Load, сеть и другие разрешения требуют собственных прогонов.

Предыдущая рабочая книга проверялась Егором на карте и в бою, все 12 позиций
и явное боевое применение седьмой. После изменения бумаги новый визуальный
прогон не подменяет собой повторное прохождение кампаний либо тест сети.

## Изоляция

Игровые проверки проводятся в отдельных копиях. Сборщик читает рабочие игры,
но проверка установки не должна менять их PAK, EXE, профили и сохранения.
Временные изменения тестовой копии инвентаризируются и затем восстанавливаются.

Путь профиля тоже требует проверки: отдельная папка EXE ещё не означает
отдельные сохранения в Documents. Для известных образов cached nstl::string
с тремя x86-указателями находится у Universe по `0xfe6ce8`, у этого H55 по
`0xfb8394`; это адреса для чтения после проверки точного EXE, не destinations
мода. В лабораторной копии UI/PRODUCT_NAME
задаёт отдельное имя native user-root, затем проверяется фактический cached root
запущенного процесса. Например, одного отсутствия новой папки недостаточно:
она может появиться лишь при первой записи профиля. Universe дополнительно имеет собственный
portable override. Этот identity PAK — средство проверки, не часть player ZIP.

Текущий MCP `h5_lab` ограничен Universe-лабораторией. Его нельзя направлять
на H55 сменой произвольного пути. Для H55 используется отдельная копия и helper,
ограниченный её полным путём и точным SHA EXE.

## Изображения и ручная проверка

Фоновый PrintWindow подтверждает лишь UI. Для оценки 3D используется видимое
окно игры с проверкой foreground-процесса. Покадровая запись ограничена клиентской
областью, одним известным игровым процессом и явной клавишей D/A. Кадры для
анализа уменьшаются до 960 пикселей по ширине; разрешение игры автоматически
production-launcher не меняет.

Для анимации нужны начало, середина и конец обоих направлений. В этой работе
первый чистый конец скрывал дефект на двух третях движения; его заметил Егор.
После общей сетки бумаги и текста Егор повторно проверил оба места и сообщил,
что они выглядят правильно. Это локальная визуальная проверка конкретного
варианта, не доказательство всех возможных ракурсов и комбинаций модов.

## Проверка 5.5 этого кандидата

Свежая установка и запуск RC19k в отдельной копии: просмотрены все шесть
боевых разворотов, по 64 кадра D/A, реальные клики вперёд/назад/закрытие,
подсказки кнопок и 12-й ячейки. «Огненный шар» из позиции 7 применён в бою:
в целевом отряде стало 970 гоблинов вместо 1000. Бой целиком не завершался;
свежий прогон кампаний и Save/Load этим не подтверждаются.
