# ADR 0006 — Установщик владеет только своими файлами

Статус: принято. Дата: 2026-11-07.

## Решение

Windows PowerShell 5.1 и CMD-обёртки; Python нужен разработчику для сборки,
игроку готового ZIP он не нужен. Системная execution policy не меняется:
`-ExecutionPolicy Bypass` действует только на запущенный процесс скрипта.

Установка создаёт `Spellbook12/`, `data/Spellbook12.pak` и при необходимости
ярлык `Spellbook12 - Play.lnk` в корне игры. Рабочий стол не меняется.
EXE/DLL, базовые архивы, карты, профили и сохранения не являются destinations.

Пути проверяются на выход из корня, дубли и допустимую область владения.
SHA-256 подтверждает целостность относительно метаданных пакета; это не
криптографическая подпись издателя.

Установка сначала проверяет всё и собирает staging внутри корня игры, потом
перемещает собственные файлы. При ошибке убирается только созданное этой
операцией. Существующие мод/PAK/ярлык вызывают отказ вместо перезаписи.
Старые `Spellbook12-grid.pak`, `Spellbook12-H55.pak`, `Spellbook7-probe.pak`
нужно отдельно сохранить и убрать; установщик не присваивает себе их владение.

Удаление сверяет все owned hashes до удаления первого файла. Затем перемещает
файлы в staging; при ошибке возвращает уже перемещённые. Если rollback сам
не завершён, staging сохраняется для восстановления. После успеха удаляются
только пустые каталоги. Добавленные пользователем файлы остаются.

Для первой беты выбран явный uninstall/install при обновлении, без попытки
сливать изменённые пользователем скрипты. Нужны права записи в выбранную папку;
установщик не вызывает UAC автоматически и не меняет права доступа.

## Проверка и код

Windows round trip использует временные каталоги с пробелами и кириллицей,
копии точных EXE и sentinel-файлы базовых данных и сохранения. Игры там не
запускаются. Проверяются install, ярлык, VerifyOnly, повторная установка,
отказ при изменённых файлах, unknown EXE, legacy PAK и запрещённый destination.

Отдельный тест удерживает PAK с FileShare.Read: hash читается, но поздний Move
падает после перемещения остальных файлов. Должны восстановиться все файлы,
очиститься staging и снова пройти VerifyOnly. Результат запуска — в validation.
