# ADR 0002 — Родная книга, размеры и текст

Статус: принято. Дата: 2026-11-07.

## Контекст

Увеличение числа ячеек в старом пространстве сжимает изображения и длинные
русские названия. Растяжение всей книги до 140% давало место, но пользователь
счёл книгу слишком большой. Уменьшенные миниатюры ухудшали читаемость.
Сетки и размеры подбирались совместно, с проверкой названий всех заклинаний.

## Решение

| Параметр | Значение |
| --- | --- |
| Сетка каждого листа | 2 столбца × 3 ряда |
| Порядок | слева `1 2 / 3 4 / 5 6`, справа `7 8 / 9 10 / 11 12` |
| Масштаб проекции книги | ширина `1.25`, высота `1.05` |
| Опорная ширина содержимого | `1.15` |
| Масштаб U внутри листа | `1.25 / 1.15` |
| Canvas outliner | `320 × 292` |
| Область иконки | `x=96..224`, `y=40..168`, исходные `128 × 128` |
| Начало текста | `(36,176)` |
| Доступная ширина текста | `248` |
| Шаблон шрифта | родной `Default 26fx` |

Камера расширяет бумагу, а U-преобразование удерживает содержимое ближе к
середине листа: шире поля, а расстояние между столбцами не растёт вместе с ними.
Высота canvas компенсирует уменьшение высоты книги. Это параметры ресурса и
проекции; одинаковые экранные пиксели на всех разрешениях не обещаны.

Матрицы камеры, обратной проекции и frustum пересобираются вместе. Иначе
картинка и геометрия, по которой движок выбирает объекты, расходятся.

Universe сохраняет два родных шаблона 26fx; пакет 5.5 оставляет текстовые
шаблоны своей редакции.

Для названий используется родной перенос `COutliner::SetData`; в текстовые
ресурсы заклинаний не вставляются ручные разрывы. Общий хук outliner ограничен
тремя проверенными адресами возврата: `0x683a10`, `0x683025`, `0x684d77`.
Для остальных вызовов исполняются исходные инструкции, восстанавливаются
EFLAGS и исходный результат x87. В видимой полосе ширина получается как
`284 - 36 = 248`, где 284 подаётся вместо исходного предела canvas.

## Полученные шишки

- Одного увеличения общей ширины недостаточно: предел текста и его UV-полоса
  должны быть согласованы. Изменение с 114/115% до 130% не решало каждый случай.
- Изменять размер иконок и шрифта одновременно неудобно для оценки: пользователь
  отдельно подтвердил возврат исходных 128-пиксельных иконок и чёткости.
- Удаление width-хука меняет центрирование и длину строк. Контроль без хука
  нельзя случайно выдать за финальную раскладку.
- Проба с началом текста 72 и сдвинутой UV-полосой не принята.
- Исключение третьего caller не является правильным исправлением переноса:
  этот путь относится и к перерисовке выделения заклинания.
- Частично видимый счётчик маны воспроизвёлся и в контрольной шестиячеечной
  книге с той же камерой. Раннюю гипотезу о его связи с width-хуком не считать
  установленной причиной; отдельного исправления маны в выпуске нет.
