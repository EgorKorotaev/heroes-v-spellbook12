# Как помочь Spellbook12

Проверки в игре, баг-репорты, идеи, переводы, документация и код — всё это
полезный вклад. Писать можно по-русски или по-английски. Начни с небольшого
конкретного наблюдения или изменения.

## Сообщить об ошибке

На опубликованном GitHub-репозитории открой **Issues → New issue → Ошибка /
Bug report**. Сначала поищи похожее сообщение; дополнительные сведения лучше
добавить к нему. Если работаешь с личным ZIP, заполни [FEEDBACK.txt](FEEDBACK.txt)
и передай автору полученного архива.
[Репозиторий и Issues](https://github.com/EgorKorotaev/heroes-v-spellbook12/issues).

Укажи, что известно:

- Версия Spellbook12 и редакция игры: Universe / 5.5, версия, имя EXE.
  Версию пакета можно найти в `release.json` рядом с `Install.cmd` или в
  установленном `Spellbook12/release.json`.
- Windows, язык игры, разрешение и оконный/полноэкранный режим, другие UI-моды.
- Запускал ли через `Spellbook12 - Play` / `Spellbook12/Launch.cmd`, появилось
  ли **Spellbook12 is ready** до загрузки карты.
- Краткие шаги, ожидаемый и фактический результат, повторяется ли ошибка.
  Для книги: карта или бой, школа, разворот, лист, ряд и столбец.
- Скриншот или короткое видео; для переворота — направление и фаза анимации.
  Для установки или запуска — полный текст ошибки.

Если можешь, приложи SHA-256 игрового EXE. Это помогает отличать похожие сборки:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\Games\Universe\bin\H5_Game.exe'
# Для проверенной 5.5: C:\Games\Heroes55\bin\MMH55_64.exe
```

Не знаешь хеш или точную версию — всё равно сообщи, что видел. Это повод
уточнить среду, а не причина откладывать полезное наблюдение.

Не прикладывай игровые EXE, DLL, целые архивы игры, закрытые данные или личные
папки профилей. Перед отправкой проверь текст ошибки и снимки на личные пути
и данные. Сохранение для воспроизведения передаётся отдельно по договорённости.

Пример:

> Universe 2.0.1, Spellbook12 0.1.0-beta.2, русский, окно 1280×960.
> Запуск через ярлык мода, ready появилось до загрузки.
> В бою открыл книгу, выбрал боевые заклинания, перелистнул вперёд.
> В конце переворота под нижней левой ячейкой на миг виден старый текст.
> Ожидал чистый лист. Повторяется 3 раза из 3; приложено короткое видео.

Это пример формата сообщения об уже исправленном дефекте, не список текущих багов.

## Предложить улучшение

Выбери форму **Предложение / Feature request** или раздел предложения в
[FEEDBACK.txt](FEEDBACK.txt). Опиши ситуацию игрока, что неудобно сейчас,
желаемый результат и варианты, которые рассматривал. Эскиз полезен, готовое
техническое решение не требуется.

Мод посвящён косметической книге. Переводы всей игры, баланс и перенос кампаний
живут отдельно. Сетевая игра и H5Lobby пока не проверены; их поддержку нужно
подтверждать отдельными тестами. Предложение не означает обещание срока реализации.

## Предложить изменение кода или документации

1. Прочитай [AGENTS.md](AGENTS.md), [сборку](docs/BUILD.txt),
   [передачу AI](docs/AI-HANDOFF.txt) и [индекс ADR](docs/adr/README.md).
2. На GitHub: создай fork и рабочую ветку, внеси небольшое законченное изменение,
   открой Pull Request. Для личной передачи можно прислать коммит, `git diff`
   или Git bundle с описанием.
3. Опиши проблему и результат, приложи уместные проверки и скриншоты.
   Для правки документации достаточно проверить ссылки и примеры.
   Код проверяй тестами; визуальные изменения — в отдельной игровой копии.

Быстрый старт из исходников:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python build.py --edition universe --game-root /path/to/Universe
```

Команды для Windows и 5.5 — в [BUILD.txt](docs/BUILD.txt). Готовый пакет игрока
не требует Python. Игру и игровые данные нужно предоставить из своей установки.

При изменении размеров или геометрии вместе проверяются вид, выбор, подсветка,
подсказки, реальные клики и оба направления переворота. Для native-кода нужна
проверка обеих поддерживаемых редакций. Для установщика — Windows round trip
из `tests/windows_roundtrip.ps1`. Честно отделяй «прошли unit-тесты» от
«проверено в игре» и перечисляй то, что не проверял.

Не обходи проверку SHA/исходных инструкций ради неизвестного EXE. Новый профиль
требует изучения адресов и ABI, сборки и отдельных игровых проверок. Не меняй
игровой EXE на диске. Сохраняй причины решений в ADR, включая неудачные пробы.
Не загружай в Git игровые бинарники и пользовательские данные.

Оригинальный код и документация принимаются под MIT; лицензия не переносится
на чужие игровые ресурсы. Указывай авторство и происхождение заимствований.
Агентские коммиты должны явно называть агента автором и коммиттером.

## English

Bug reports, testing, ideas, translations, documentation and code are welcome.
Use **Issues → New issue → Bug report / Feature request**, or fill in
[FEEDBACK.txt](FEEDBACK.txt) when receiving a private ZIP. Include the game/mod
version, launch method, resolution, reproduction steps and expected/actual result.
Screenshots or short clips help. Never upload full game files or personal profiles.

For code contributions, read [BUILD.txt](docs/BUILD.txt),
[AI-HANDOFF.txt](docs/AI-HANDOFF.txt) and the ADR index first. Make a focused PR,
state what was tested, preserve exact-build guards and use isolated live tests.
Original contributions use MIT; game resources retain their own provenance.
